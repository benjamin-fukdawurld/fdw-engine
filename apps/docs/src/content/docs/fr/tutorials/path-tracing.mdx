La rastérisation éclaire chaque point par les seules lumières, plus une
lumière ambiante uniforme. Pourtant la lumière rebondit : le mur rouge
teinte le sol, le plafond éclairé par le sol éclaire la pièce. Un **path
tracer** suit la lumière à rebours : depuis la caméra, à travers chaque
pixel, en rebondissant sur les surfaces jusqu'à trouver une lumière.

<Example name="path-tracing" />

L'image commence granuleuse et s'éclaircit à mesure que les images
s'additionnent. Cliquez sur le canevas : la caméra bouge, puis la
rastérisation de la même scène.

## Le path tracer

```ts
import { PathTracer, RayScene } from '@fdw/engine-raytracing';

const tracer = new PathTracer(renderer, new RayScene(backend), {
  bounces: 4,
  sky: { zenith, horizon, ground }, // ce que voient les rayons perdus
});

onFrame((time) => {
  tracer.scene.update({ items });
  tracer.render({ camera, surface, lights: [light], time });
});
```

Plutôt que le dégradé de `sky`, les rayons perdus peuvent voir un
[environnement](/fdw-engine/fr/tutorials/environment-lighting/), le même que
celui que reflète la rastérisation : `tracer.render({ camera, surface,
lights, environment })`. Les lumières sont lues dans le format du pool de
lumières du renderer.

La même scène, les mêmes matériaux que la rastérisation : un matériau
compilé pour les points touchés par les rayons donne les paramètres de la
BSDF du modèle `pbr` (couleur de base, métal, rugosité, normale,
émission) ; les matériaux `unlit` sont des sources de lumière (leur couleur
est leur émission).

## Une image

Tous les pixels à la fois, en vagues de passes de calcul :

1. **Les rayons de la caméra**, à travers un point au hasard de chaque
   pixel (l'anticrénelage vient avec les images).
2. Pour chaque rebond : **tracer** les rayons (l'impact le plus proche) ;
   **les surfaces** touchées, un dispatch par matériau de la scène ; puis
   **le rebond** : l'émission de la surface, la lumière d'une lumière tirée
   au hasard (un rayon d'ombre vers elle), et la direction suivante, tirée
   selon la BSDF (un lobe diffus ou spéculaire, le poids du chemin ajusté
   par la densité). Après deux rebonds, les chemins qui portent peu de
   lumière s'arrêtent au hasard (la roulette russe). Les pixels masqués et
   mélangés laissent passer le rayon.
3. **L'accumulation** : l'image mêlée à l'historique de chaque pixel
   (plus bas) ; la moyenne est l'image.
4. **Le filtre** : tant que les images d'un pixel sont peu nombreuses, un
   filtre à trous lisse le bruit entre les pixels qui partagent une surface
   (normales et profondeurs proches), en divisant par l'albédo pour que les
   textures restent nettes.

## Le bruit

Un chemin trouve la lumière par hasard : là où la lumière est difficile à
atteindre, les premières images sont granuleuses.

- **Les lumières** (`lights`) sont atteintes exprès, par un rayon d'ombre :
  elles font peu de bruit. Une surface émissive n'est trouvée qu'en
  rebondissant dessus : petite et brillante, elle fait des lucioles.
  Éclairez une lampe avec une lumière à sa place (l'exemple met une lumière
  ponctuelle sous son panneau).
- `maxRadiance` (8) écrête les échantillons les plus brillants : moins de
  bruit, un peu moins de lumière.
- Plus d'images : la moyenne converge, à peu près comme la racine carrée de
  leur nombre.

## Une caméra qui bouge

Le premier impact de chaque pixel est gardé avec son image : le point vu,
sa normale. Quand la caméra ou les objets bougent, chaque pixel cherche le
point qu'il voit dans l'image précédente (projeté avec la caméra
précédente), entre les quatre pixels autour, et garde leur historique là
où ils voyaient la même surface (un point et une normale proches des
siens). Ce qui était caché, ou un objet qui bouge, repart d'une image.

```ts
const tracer = new PathTracer(renderer, scene, {
  history: 16, // les images qu'un pixel garde quand tout bouge
});
```

Quand tout bouge, un pixel garde ses `history` dernières images : moins,
moins de flou derrière ce qui bouge et plus de bruit ; immobile, les
images s'additionnent sans fin. Changer les lumières ou les matériaux fait
tout recommencer (`tracer.reset()` aussi). L'image en mouvement reste plus
bruitée qu'une image fixe : le path tracer convient à un aperçu, une
image, une caméra lente.

## Plus vite sur Vulkan

Sur Vulkan, les noyaux qui tracent des rayons peuvent tourner en
**pipelines de ray tracing** (`VK_KHR_ray_tracing_pipeline`) : le matériel
ordonne les rayons et leurs impacts, le test de l'alpha dans un shader
any-hit. L'image est la même :

```ts
new PathTracer(renderer, scene, { rayTracingPipeline: true });
```

Là où le backend n'en a pas (WebGPU, ou un GPU sans eux), l'option revient
aux ray queries.
