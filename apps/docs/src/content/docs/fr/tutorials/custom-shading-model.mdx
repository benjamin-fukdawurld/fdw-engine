Un modèle d'éclairage transforme les propriétés d'une surface en couleur, à
partir des lumières de l'image. `unlit`, `phong` et `pbr` sont fournis avec le
moteur ; cette page en écrit un autre, le **toon shading** : la lumière reçue,
arrondie à l'inférieur sur quelques bandes uniformes.

<Example name="toon-shading" />

## Un modèle est un function graph

Un **function graph** est un graphe utilisé comme nœud : ses `functionInput`
sont les entrées du nœud, ses `functionOutput` ses sorties. Un modèle
d'éclairage est un function graph avec :

- les entrées de surface qu'il accepte : ici `baseColor`, `bands`, `normal` ;
- une entrée `worldPosition`, de type `vec4` ;
- une unique sortie `color`, de type `vec4`.

```ts
const registry = createStandardRegistry();
const f = new GraphBuilder('toon', registry);
const baseColor = f.functionInput('baseColor', BuiltinTypes.vec3f, {
  default: [1, 1, 1],
});
const bands = f.functionInput('bands', BuiltinTypes.f32, { default: 3 });
const normal = f.functionInput('normal', BuiltinTypes.vec3f);
const position = f.functionInput('worldPosition', BuiltinTypes.vec4f);
```

Une entrée sans valeur par défaut doit être connectée, sauf `normal` :
lorsqu'une surface l'omet, le modèle reçoit la normale interpolée du mesh.

## Additionner les lumières

`light.current` est la lumière en cours d'addition, et `light.sum` additionne
son entrée `value` sur toutes les lumières de l'image. Tout ce qui se trouve
entre les deux est calculé une fois par lumière, dans une boucle générée par
le compilateur :

```ts
const light = f.node(stdLights.current);
// The direction to the light: position.w is 0 for a directional light,
// whose position is the direction it comes from.
const toLight = f.call(std.normalize, {
  x: f.call(std.sub, {
    a: light.position.swizzle('xyz'),
    b: f.call(std.mul, {
      a: position.swizzle('xyz'),
      b: light.position.swizzle('w'),
    }),
  }),
});
// The intensity of the light: the mean of its diffuse color.
const intensity = f.call(std.dot, {
  a: light.diffuse,
  b: [1 / 3, 1 / 3, 1 / 3],
});
const received = f.call(stdLights.sum, {
  value: f.call(std.mul, {
    a: f.call(std.max, {
      a: f.call(std.dot, {
        a: f.call(std.normalize, { x: normal }),
        b: toLight,
      }),
      b: 0,
    }),
    b: intensity,
  }),
});
```

`light.current` fournit aussi les couleurs de la lumière (`ambient`,
`diffuse`, `specular`), ses facteurs d'`attenuation` et son cône de spot.
`light.shadow` donne sa visibilité en un point, à partir des shadow maps :
multipliez la lumière par cette valeur pour recevoir les ombres.

## Les bandes, et la couleur

```ts
const level = f.call(std.div, {
  a: f.call(std.floor, {
    x: f.call(std.mul, { a: f.call(std.saturate, { x: received }), b: bands }),
  }),
  b: bands,
});
f.functionOutput(
  'color',
  f.call(std.extend, {
    xyz: f.call(std.mul, {
      a: baseColor,
      b: f.call(std.mix, { a: 0.25, b: 1, t: level }),
    }),
    w: 1,
  })
);
registry.register(defineShadingModel('toon', f.build()));
```

`defineShadingModel` vérifie le contrat (l'entrée `worldPosition`, la sortie
`color`) et nomme le nœud `lighting.toon`.

## L'utiliser

La surface d'un matériau nomme le modèle ; ses entrées sont désormais celles
du modèle, vérifiées comme pour tout autre nœud :

```ts
const g = new GraphBuilder('cartoon', registry);
g.surface({
  shadingModel: 'toon',
  baseColor: g.uniform('color', BuiltinTypes.vec3f),
  bands: g.uniform('bands', BuiltinTypes.f32),
});

const renderer = new Renderer(backend, { registry });
```

`g.build()` embarque les function graphs appelés par le matériau, si bien
qu'un matériau enregistré en JSON se compile sans avoir à les réenregistrer.
Le renderer reçoit lui aussi le registre, pour les types de nœuds qu'il
compile.

Le compilateur inline la fonction : le programme obtenu est celui que vous
auriez en écrivant les nœuds dans le matériau, optimisé de la même façon. Le
tone mapping et l'encodage de la sortie s'appliquent après le modèle, comme
pour les modèles standard.
