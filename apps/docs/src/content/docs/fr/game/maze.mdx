## 1. Générer le labyrinthe

Un labyrinthe est une grille de cellules, chacune avec quatre murs. Le
générateur parcourt la grille en profondeur d'abord — le « recursive
backtracker » : depuis une cellule, il va vers une voisine au hasard pas
encore visitée et ouvre le mur qui les sépare ; lorsqu'il ne reste aucune
voisine, il revient en arrière. Chaque cellule est alors atteignable, par un
seul chemin.

```ts title="maze/maze.ts"
export const Wall = { North: 1, East: 2, South: 4, West: 8 } as const;

export function generateMaze(width: number, height: number, seed = 1): Maze {
  const random = seededRandom(seed);
  const cells = new Uint8Array(width * height).fill(15); // four walls each
  const visited = new Uint8Array(width * height);
  const stack = [0];
  visited[0] = 1;
  while (stack.length > 0) {
    const cell = stack[stack.length - 1];
    const x = cell % width;
    const z = Math.floor(cell / width);
    const open = directions.filter(({ dx, dz }) => /* inside, not visited */);
    if (open.length === 0) {
      stack.pop(); // a dead end: back
      continue;
    }
    const { dx, dz, wall, opposite } = open[Math.floor(random() * open.length)];
    const next = (z + dz) * width + x + dx;
    cells[cell] &= ~wall; // open the wall on both sides
    cells[next] &= ~opposite;
    visited[next] = 1;
    stack.push(next);
  }
  return { width, height, cells };
}
```

Les murs sont des bits d'un `Uint8Array` : compacts, et rapides à tester. Le
générateur aléatoire a une graine (`seededRandom()`, un mulberry32) : la même
graine donne le même labyrinthe, ce qui compte pour les tests et pour
partager un niveau.

## 2. Construire le niveau

Chaque cellule devient une dalle de sol ; chaque côté fermé, un mur. Les deux
sont des cubes, mis à l'échelle :

```ts title="maze/level.ts"
const floorGroup = scene.root.add({ name: 'floor', static: true });
const wallGroup = scene.root.add({ name: 'walls', static: true });
for (let z = 0; z < maze.height; z++) {
  for (let x = 0; x < maze.width; x++) {
    const { x: cx, z: cz } = cellCenter(x, z);
    floorGroup
      .add({
        position: { x: cx, y: -0.05, z: cz },
        scale: { x: cellSize, y: 0.1, z: cellSize },
        static: true,
      })
      .setMesh(cube, floor);
    // The north and west walls of each cell, the south and east ones on
    // the last row and column: each wall once.
    for (const { bit, dx, dz, along } of sides) {
      if (walls & bit) {
        wallGroup
          .add({ position, scale, static: true, occluder: true })
          .setMesh(cube, wall);
      }
    }
  }
}
```

Trois choix comptent ici :

- **Nœuds statiques.** Le niveau ne bouge jamais : `static: true` indique à
  la scène de calculer ces nœuds une seule fois, et de les indexer tous d'un
  coup dans un index spatial qui leur est propre (un octree construit de haut
  en bas), à la première frame.
- **Occluders.** Les murs cachent ce qui se trouve derrière eux :
  `occluder: true` les marque. Vu de dessus, un labyrinthe cache peu de
  chose : le jeu le dessine sans
  l'[occlusion culling](/fdw-engine/fr/tutorials/occlusion-culling/), qui
  est rentable au niveau des rues.
- **Groupes.** `floor` et `walls` sont des nœuds sans mesh : ils organisent
  la hiérarchie (`level.walls.children` liste les murs) sans rien coûter au
  dessin.

## 3. Le clavier, la souris et la manette

Le jeu lit ses entrées avec `@fdw/engine-input`. L'origine des événements
est donnée par la page ou l'application — un `WebInputSource` sur le
canvas, un `NativeInputSource` sur une fenêtre native — et le jeu construit
un `Input` dessus :

```ts title="maze/step1.ts"
const input = new Input(context.input ?? new FakeInputSource());
const actions = mazeActions(input);
```

Le code du jeu ne lit pas de touches : il lit des **actions**, déclarées
une fois avec leurs liaisons — le clavier, et la manette :

```ts title="maze/controls.ts"
move: {
  type: 'vector',
  bindings: [
    { up: 'key:KeyW', down: 'key:KeyS', left: 'key:KeyA', right: 'key:KeyD' },
    { up: 'key:ArrowUp', down: 'key:ArrowDown', left: 'key:ArrowLeft', right: 'key:ArrowRight' },
    'gamepad:leftStick',
  ],
},
turn: {
  type: 'axis',
  bindings: [
    { negative: 'key:KeyE', positive: 'key:KeyQ' },
    { negative: 'gamepad:rightShoulder', positive: 'gamepad:leftShoulder' },
  ],
},
```

- `KeyW` est une **position** sur le clavier, pas une lettre : sur un
  clavier AZERTY, la même touche est Z, et le jeu se joue avec ZQSD sans
  configuration.
- `move` est un vecteur, x vers la droite et y vers l'avant, de longueur 0
  à 1 : quatre touches, ou un stick. La liaison la plus forte l'emporte.

Chaque frame commence par `input.update()` : il applique les événements
reçus depuis la frame précédente et lit les manettes, puis l'état reste le
même pendant la frame. Se déplacer tant qu'une touche est enfoncée revient
alors à multiplier une vitesse par la durée de la frame.

Voir [Entrées](/fdw-engine/fr/guides/input/) pour l'ensemble de l'API.

## 4. La caméra

La caméra est un nœud de la scène : `setCamera(camera)` lui fait suivre le
nœud, en regardant le long de son axe −z. La caméra libre déplace le nœud :

```ts title="maze/flyCamera.ts"
update(dt: number): void {
  const speed = (actions.button('run').down ? 3 : 1) * (5 + this.height) * dt;
  const { x: right, y: forward } = actions.vector('move');
  this.x += (right * cos - forward * sin) * speed;
  this.z += (-right * sin - forward * cos) * speed;
  this.yaw += actions.axis('turn') * 1.5 * dt;
  // A notch of the wheel: 10 %; the pad held: twice as high per second.
  const zoom = actions.axis('zoomStep') * 0.1 + actions.axis('zoom') * dt;
  this.height *= Math.exp(zoom);
  this._node.transform.position = { x: this.x, y: this.height, z: this.z };
  this._node.transform.rotation = multiply(around('y', this.yaw), around('x', this.pitch));
}
```

La rotation est un lacet (autour de la verticale) puis un tangage (vers le
bas) : le produit de deux quaternions. La vitesse croît avec la hauteur, de
sorte que le labyrinthe défile au même rythme quel que soit le zoom.

## 5. Le rendu : la vue principale

`renderer.render({ source: scene, … })` suffirait pour une vue. La vue de
dessus en demande une seconde dans la même frame, donc la frame est un render
graph :

```ts title="maze/view.ts"
const graph = new RenderGraph();
const output = graph.importTexture('surface', surface.getCurrentTarget());
const main = renderer.addScenePasses(graph, {
  source: scene,
  camera,
  layers: ~TopViewLayer, // everything but the marker of the top view
  target: output,
  format: surface.format,
});
topView.add(graph, main.color, surface);
runner.execute(graph);
surface.present();
```

Le renderer demande à la scène ce qui se trouve dans le frustum de la
caméra : sur les 4700 nœuds, quelques centaines. La ligne sous le canvas
indique combien, et combien sont dessinés dans la shadow map du soleil —
seulement ceux dont les ombres peuvent tomber dans la vue.

## 6. La vue de dessus

La vue de dessus dessine le niveau vu d'en haut, avec une caméra
orthographique, mais seulement les nœuds que la caméra principale a retenus.
La scène mémorise, sur chaque nœud, la dernière requête de caméra qui l'a
gardé (`NodeState.lastVisible`) ; la vue de dessus donne au renderer une
source qui filtre selon cette valeur :

```ts title="maze/topView.ts"
const { lastVisible, layers } = scene.NodeState;
this._source = {
  query: (frustum, mask, visit) =>
    scene.query(
      frustum,
      mask,
      (item) => {
        const entity = item.entity;
        if (
          lastVisible[entity] === this._stamp ||
          layers[entity] === TopViewLayer
        ) {
          visit(item);
        }
      },
      'shadow'
    ), // not a camera query: it must not change what was retained
  lights: () => scene.lights(),
};
```

La vue de dessus est dessinée dans une petite texture, puis par-dessus la vue
principale par une passe plein écran qui ne couvre qu'un coin de l'écran : un
matériau qui lit la texture dans un rectangle, transparent ailleurs, mélangé
(`blend: true`) :

```ts
const local = (uv - rect.xy) / rect.zw; // where the pixel is in the rectangle
const inside =
  step(0, local.x) * step(local.x, 1) * step(0, local.y) * step(local.y, 1);
color = vec4(texel.rgb * inside, max(inside, frame * 0.8));
```

Le repère de la caméra est une sphère sur une couche qui lui est propre
(`TopViewLayer`) : la vue principale, dont les couches sont `~TopViewLayer`,
ne la voit pas.

## Ce que nous avons

- Un monde de milliers de nœuds statiques, indexés une seule fois, et
  dessinés seulement là où regarde la caméra.
- Une frame composée de deux vues dans un render graph, assemblées par une
  passe plein écran mélangée.
- Des entrées qui fonctionnent de la même façon dans une page, dans la démo
  et dans une fenêtre native.
