The character walks straight, then turns left. Nothing in the code says
how fast it goes or how sharply it turns: the **clips** do. Their hips
travel forward and turn; the animator takes that movement out of the
poses — the character animates in place — and gives it to the code, which
moves the character with it. The feet do not slide: the movement is the
one the animator drew.

## Clips that travel

The model of the [animated character](/fdw-engine/tutorials/character-animation/)
has two clips for this: `Walk_RM`, whose hips go forward at 1.3 m/s, and
`TurnLeft_RM`, whose hips go forward while turning a twelfth of a turn a
cycle. The other clips (`Walk`, `Run`…) are **in place**: their hips stay
over the origin, the code chooses the speed. Asset packs often ship both,
the root motion ones with a suffix (`_RM`, `_Root`).

## The animator takes the movement

```ts
import { Animator, rootMotionToWorld } from '@fdw/engine-animation';

const animator = new Animator(graph, {
  skeleton,
  clips,
  rootMotion: { joint: 'hips', rotation: true },
});
```

With `rootMotion`, each update of the animator:

- **takes out of the poses** the movement of the joint along x and z (and
  its turn around y, with `rotation: true`): the hips stay where they are
  at the start of each clip, facing as they face there;
- **adds up** what that joint travelled during the update, in
  `animator.rootMotion`: `x`, `y`, `z` in the space of the character as it
  faced at the start of the update, and `yaw`, radians around y.

The movement goes through the graph as the poses do: a blend weighs the
movements of its inputs, a cross-fade of a state machine too, a loop adds
a whole cycle each time the clip wraps, a clip that does not loop stops at
its end. The **layers** do not move the character: a wave of the hand on
a layer leaves the walk underneath alone.

The vertical movement stays in the poses (the bob of the steps) unless
`vertical: true`: then a jump clip lifts the character itself.

## Moving the character

```ts
let heading = 0;
const step = { x: 0, y: 0, z: 0 };

animator.update(dt);
const motion = animator.rootMotion;
rootMotionToWorld(motion, heading, 1, step); // turned by the heading, scaled
heading += motion.yaw;

controller.move({ x: step.x, y: -fall * dt, z: step.z });
node.transform.rotation = axisAngle(0, 1, 0, heading);
```

`rootMotionToWorld` turns the movement by the heading of the character
and scales it by the scale of its node. The code keeps the last word: it
can add gravity, slow the character on ice, or refuse the movement.

Here, a **character controller** moves the character against the scene,
so the crates stop it: a `SceneCharacter`, which needs no physics engine
(see [Navigation](/fdw-engine/tutorials/navigation/)). A
`PhysicsCharacter` of Rapier takes the same `move`.

## In place or root motion?

| In place                                            | Root motion                                                                     |
| --------------------------------------------------- | ------------------------------------------------------------------------------- |
| The code chooses the speed; the clip follows        | The clip chooses the speed; the code follows                                    |
| Instant, precise controls (a shooter, a platformer) | Weighty moves, no foot sliding: starts, stops, turns, attacks that step forward |
| The clips' speeds matched by hand (`rate`)          | Nothing to match                                                                |

Both mix well: locomotion in place, and root motion for the attacks and
the dodges, in the same graph — only the clips that travel move the
character.
